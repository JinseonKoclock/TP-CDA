Installer et configurer le Téléporteur afin de disposer d'un environnement Linux prêt à l'emploi pour suivre la formation O'clock.

Configurer également les principaux outils de travail (VirtualBox, Slack, VS Code...) avant le début des premiers challenges.

Aucun développement applicatif.

---

## ⚠ Les principales difficultés

### Trouver le Téléporteur

Au début, je cherchais directement un lien de téléchargement du Téléporteur.

Comme je ne le trouvais pas, j'ai passé beaucoup de temps à chercher dans la documentation alors qu'il suffisait simplement de suivre les étapes du guide.

Cette expérience m'a montré qu'il est souvent plus efficace de lire complètement la documentation avant de chercher une solution compliquée.

---

### Configuration de VirtualBox

Plusieurs options de VirtualBox me semblaient inconnues :

- mémoire vidéo ;
- affichage sur plusieurs écrans ;
- différentes options de configuration.

J'ai préféré vérifier chaque étape avant de continuer afin d'éviter une mauvaise configuration.

---

### Découverte de Linux et du terminal

Je n'avais pratiquement jamais utilisé un terminal Linux auparavant.

Au début, je ne comprenais pas encore :

- ce qu'était Bash ;
- pourquoi utiliser un terminal plutôt qu'une interface graphique ;
- les commandes Linux les plus simples.

J'ai commencé à apprendre les commandes de base (`pwd`, `ls`, `cd`, `cp`, `mkdir`, etc.) et leur utilité.

---

### Premiers réglages de VS Code

Lors du premier lancement de VS Code, plusieurs écrans de configuration sont apparus.

Je ne savais pas quelles options étaient réellement importantes et je me suis rapidement senti perdu.

J'ai également eu des difficultés à ouvrir le terminal intégré de VS Code car je cherchais dans les paramètres au lieu d'ouvrir directement un nouveau terminal.

J'ai finalement décidé de continuer le challenge avant de revenir sur cette configuration plus tard.

---

### Premiers pas avec Git

À la fin du premier challenge, je devais envoyer mon travail sur GitHub.

Je ne comprenais pas encore le rôle du *staging* ni la différence entre les branches **master** et **main**.

J'ai commencé à comprendre le cycle de base :

```
git status
→ git add
→ git commit
→ git push
```
